# VectorEffects 0.1.7 Beta

This update adds an MCP service, so an AI client on the same computer can drive
the application, and changes the Zarr export to the routing layout.

**This beta expires on January 1, 2027.** Install a newer version before that
date to continue using VectorEffects.

## Downloads

Choose an installer from the release's Assets list:

| System | File |
| --- | --- |
| Intel Mac | `_x64.dmg` |
| Apple Silicon Mac (M-series) | `_aarch64.dmg` |
| Windows 64-bit | `-setup.exe` or `.msi` |

`SHA256SUMS` contains checksums for the downloadable installers and app archives.
Mac builds without Developer ID credentials use ad-hoc signing without
notarization. Windows installers are unsigned; the operating system may require
approval before launch.

## New

- **MCP service.** Settings → MCP service lets an AI client on this computer open and edit projects, animate, import, export, and take pictures of the map. Every tool calls the same command the interface calls, so a client's edits appear as they happen and undo like your own. It is **off by default**. While on it listens on `127.0.0.1` only, behind a bearer token, and refuses requests whose `Host` or `Origin` is not a loopback name; while off there is no socket at all. **Rotate token** revokes the old one. The status bar shows MCP and the last tool while a client is connected.
- **Add to Claude Code** and **Add to Codex** write the service into that client's own configuration, and update it after a rotated token or a changed port. Claude Code is registered through its own `claude mcp add`; Codex by an entry in `~/.codex/config.toml`, with the rest of the file left as it was. *Configuration for other clients* holds the same thing as text to copy. Both files then hold the token, as the application's own settings file does; on macOS and Linux all three are readable by your account only.

## Changed

- **The Zarr export is a different format, and a store exported by 0.1.6 is not in it.** Export Zarr now writes the routing layout:
  - One Float16 `data` array with dimensions `(time, param, latitude, longitude)`, beside `time`, `param`, `latitude` and `longitude` coordinate arrays. `param` is `u10`, `v10`, `ucur`, `vcur`. `time` is hours since the reference time the dialog asks for, with CF units.
  - Latitude runs from 90° to one step short of −90° and longitude from −180°, so the Atlantic is contiguous. The south pole row is left out so that ten degrees divides the axis. Every cell is still evaluated at the same point the GRIB export evaluates it.
  - Inner chunks are three days by 10° by 10° — 72 hourly steps, 24 three-hourly, 12 six-hourly or 3 daily — compressed with Zstd level 5, and gathered by the `sharding_indexed` codec into ocean-basin shards on a rectilinear chunk grid. The group's attributes name the twenty shards.
  - A chunk with no field in it is not stored, and a shard with no chunk in it is not a file, so a regional project's store is the size of the region. A reader that follows the Zarr specification reads both as NaN.
  - The `reference_time`, `step_hours` and grid-origin attributes of 0.1.6 are gone: the coordinate arrays carry that now.
  - zarr-python 3.4 (with `array.rectilinear_chunks` enabled) and `zarrs` read the store. **xarray cannot open a rectilinear chunk grid yet**; read the arrays through zarr-python directly.

## Fixes and improvements

- The settings file is written owner-only on macOS and Linux.
- Help documents the MCP service and the new Zarr layout.

Each installer build repeats the native/UI checks, generated-binding check, and
offline check on its own platform before bundling.
