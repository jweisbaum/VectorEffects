# VectorEffects 0.1.8 Beta

This update makes the MCP service do the right thing when an AI client is
asked for weather in plain words, adds a one-press install for Claude Desktop,
and tidies the Settings dialog.

**This beta expires on January 1, 2027.** Install a newer version before that
date to continue using VectorEffects.

## Downloads

Choose an installer from the release's Assets list:

| System | File |
| --- | --- |
| Intel Mac | `_x64.dmg` |
| Apple Silicon Mac (M-series) | `_aarch64.dmg` |
| Windows 64-bit | `-setup.exe` or `.msi` |
| Linux 64-bit | `.AppImage`, `.deb`, or `.rpm` |

`SHA256SUMS` contains checksums for the downloadable installers and app archives.
Mac builds without Developer ID credentials use ad-hoc signing without
notarization. Windows installers are unsigned; the operating system may require
approval before launch.

## New

- **Add to Claude Desktop.** Settings → MCP service opens a VectorEffects extension in Claude Desktop's own installer, where you confirm it. The extension is a small bridge between Claude Desktop and the MCP service on this computer. It holds no token: it reads the port and token from VectorEffects' settings as it goes, so it is installed once and keeps working after a new token or port. If VectorEffects is closed or the service is off, it says so and connects when VectorEffects is back. The extension is unsigned, which Claude Desktop mentions when installing. macOS and Windows.
- **Real past weather, asked for in plain words.** Asked for "a GRIB of Hurricane Helene" or "the weather from the last Newport Bermuda Race", a client now finds the dates, downloads the observed wind with **import_history**, and exports it — where 0.1.7 drew a storm by hand. The service tells the client today's date, so "the last" means the last.
  - `history_archives` lists what can be downloaded and between which dates, as held right now.
  - `import_history` takes `fields` (`"wind"`, `"current"`) and ISO 8601 times, sizes the timeline to the range and stamps its start time; `export_grib` then needs only a path.
- **`storm_create`** draws a travelling cyclone in one call: a single circle object, turning counter-clockwise in the northern hemisphere and clockwise in the southern, strongest at its centre, keyed along a track with its peak wind and size running from a start value to an end value — so a storm intensifies as it travels.

## Changed

- **MCP clients written against 0.1.7 need these changes:**
  - `import_history` takes `fields`, `start` and `end` (ISO 8601 UTC) instead of `archives`, `start_unix_s` and `end_unix_s`. The archive name 0.1.7 documented, `"era5"`, was one it refused.
  - `tool_catalogue` returns `{ "tools": [...] }` and `recent_projects` returns `{ "projects": [...] }`; the catalogue takes an optional `tool` name for one entry.
  - Every path must be absolute or begin with `~/`. A relative path used to land in the application's own folder.
  - `export_grib` and `export_zarr` take their reference time from the project's start time when none is given.
- Every tool's schema is now one a strict MCP client accepts. In 0.1.7 the official MCP SDK refused the whole tool list, and other clients could not call `object_create` without the `invoke` escape hatch.
- Setting a property at a step past the end of the timeline is refused; it used to write a keyframe no frame would show.

## Fixes and improvements

- The Settings dialog's Autosave, Units, Display, Macros and MCP sections are left-aligned, each label above its control, and the MCP switch sits on one row with its text. A long token no longer squeezes the Rotate token button.

Each installer build repeats the native/UI checks, generated-binding check, and
offline check on its own platform before bundling.
